# 美亚入库助手 V1.0

把「供应商单据」变成「美亚美牙能直接导入的两张表」的本地小工具。

支持三种来源：牙e在线订单、梅苗苗订单、手机拍的对账单照片（也可直接给 Excel/CSV）。
输出两张表：**建档表**（products.xlsx，新物品先建档）与 **入库表**（inbound_<供应商>.xlsx，按供应商分组）。
中间夹着一个本地 SQLite 产品库，用来记住「这个物品已经建过档、物品编号是多少」。

> 一句话：**它只负责出表，不负责入库。**
> 表出好了，你自己导进美亚；导完了，回界面上点一下「确认入库」，台账才记这一笔。

## 为什么要它

一家口腔诊所每月进几次耗材，每次的单据来自不同平台、不同格式：

- 牙e在线导出的订单 Excel，列名和顺序随平台改版变；
- 梅苗苗的销售清单，表头在第 2 行、金额是中文大写；
- 供货商随货单是手机拍的，有折痕、有阴影、还是歪的。

人工做的话，一遍流程是：看单 → 抄物品名 → 查产品库里有没有 → 没有的先去美亚建档 →
建档表导进美亚 → 等美亚给物品编号 → 再回来做入库表 → 导进美亚。
一张单 30 行，做两小时，而且**最容易错的地方不是慢，是漏**：某一行忘了建档，
入库时美亚整行拒绝；同一个物品两批各建了一次档，产品库里出现两条重复档案。

这个工具把这套流程固化成可重跑的步骤，并且**把需要人拍板的地方单独挑出来问你**，
其余的全自动。

## 核心原则

1. **不读美亚的数据。** 代码里在 socket 层下了闸（`tools/no_meiya.py`），
   任何指向 `myyun.com` 的连接直接抛异常。产品库是你自己导出的 `产品库.xls`
   传进来的，不是程序去美亚抓的。
2. **出表 ≠ 入库。** 台账记「已出表」，点「确认入库」才记「已入库」。
   程序不知道你到底导没导，所以只能问你。
3. **抽不出来就明说，不猜。** 表头认不出、注册证读成乱码、效期缺失 —— 一律阻断并写进
   `warnings`，宁可让你手填一行，也不替你编一个值。
4. **同一批只出一套表。** 一个订单出一张表是效率灾难；一批单据合并成两张表，
   同一物品只建一次档。

## 它做什么（功能）

| 环节 | 能力 |
| --- | --- |
| 拉单 | 牙e在线 / 梅苗苗，按日期范围拉订单（走本机已登录的浏览器，不碰账号密码） |
| 读表 | 按**表头签名**识别模板，不认文件名；支持 .xls/.xlsx/.xlsm/.csv 与照片 |
| 读照片 | PaddleOCR + 坐标重排 + 纠偏放大，按 profile 里的表头关键字认列（可选装） |
| 产品库 | 本地 SQLite（`data/local.db`），按「注册证主号+规格+品牌」认身份 |
| 建档 | 库里没有的 → 出建档表；有歧义（同身份多条档案）→ 让你选一条，不瞎猜 |
| 入库 | 已建档的 → 出按供应商分组的入库表 |
| 卡点 | 效期不足一年 → 等你审批；赠品/样品 → 可整单或单行标「禁止入库」 |
| 台账 | 出表记账、点「确认入库」才算入库、可与历史台账核对 |
| 界面 | 本地网页（`127.0.0.1:8799`），点按钮就能处置，不用记命令行 |

## 安装

需要 **Python 3.9+**（开发和实测用的是 3.12）。

```bash
git clone <本仓库地址> meiya-inbound-assistant
cd meiya-inbound-assistant
python -m pip install -r requirements.txt
```

可选（只有走「照片识别」才需要，体积较大）：

```bash
python -m pip install paddlepaddle paddleocr
```

没装也能跑：照片通道会提示缺依赖，表格通道不受影响。

## 第一次使用

### 1. 准备产品库

从美亚导出一次 **产品库.xls**（物品编号 / 内部编号 / 物品名称 / 规格 / 品牌 / 注册证 等），
然后在界面上传：打开界面 → 「导入产品库」→ 选文件。
程序读进 `data/local.db`，之后所有判断都以它为准。

> 没有产品库也能跑，只是每一行都会判成「待建档」，全进建档表。

### 2. 启动

Windows 双击 `scripts\start.bat`，或：

```bash
python tools/ui.py --port 8799
```

浏览器会自动打开 `http://127.0.0.1:8799`。

### 3. 跑一批

界面上「选目录」→ 选单据所在目录 → 「开始」。等进度条走完，
结果表里每一单一个状态，需要你处置的会亮红灯并给出「处理待办」按钮。

### 4. 导表

- 状态是「可入库」的行 → 打开 `inbound_<供应商>.xlsx`，导进美亚「采购入库」；
- 状态是「待建档」的行 → 先导 `products.xlsx` 进美亚「产品库」，
  建档成功后再导入库表；
- 导完了，回到界面点 **确认入库**，台账才记这一笔。

详细操作见 [docs/USAGE.md](docs/USAGE.md)。

## 命令行

界面不是必需的，所有步骤都能命令行跑：

```bash
# 从目录出表（不拉单）
python tools/pipeline.py --in D:\单据\2026-11 --out out\2026-11 --inner-base 92000

# 从平台拉单，再出表
python tools/pipeline.py --pull yae --pull-from 2026-11-01 --pull-to 2026-11-30 --out out\11月

# 只读单据、看看能不能认出来，不出表
python tools/run.py --in D:\单据 --dry-run

# 台账
python tools/ledger.py list
```

## 配置

| 文件 | 作用 | 要改吗 |
| --- | --- | --- |
| `config/platform_sources.json` | 平台与「本店收货单位名」 | 建议改：填自己的诊所名 |
| `config/supplier_doc_prefixes.json` | 单据号前缀 → 供应商名 | 按需加 |
| `config/manufacturer_aliases.json` | 注册证/别名 → 生产厂家法定名 | 按需加，见下 |
| `config/brand_aliases.json` | 品牌别名 | 按需加 |
| `config/photo_profiles/*.json` | 照片版式（表头关键字、停止词） | 换版式才改 |
| `config/template_mapping/*.yaml` | 表格版式的列映射 | 换版式才改 |
| `config/expiry_approvals.json` | 效期审批记录（程序写） | 不用手改 |
| `config/inbound_rejects.json` | 禁止入库记录（程序写） | 不用手改 |
| `config/inbound_ledger.json` | 台账（程序写） | 不用手改 |
| `config/manual_fixes.json` | 人工处置记录（程序写） | 不用手改 |
| `config/inbound_overrides.json` | 同身份多档案时指定用哪一条 | 程序写，出歧义时自动加 |

仓库里这几个「程序写」的文件都是空壳（`{"version":1,"records":[]}`），
程序找不到文件也不会报错，会按空的处理。

**凭据不进仓库**：`config/yae_token.json`、`config/mmm_token.json` 是程序
从本机浏览器里读出来的登录态，`.gitignore` 已排除。永远不要提交它们。

## 关于「生产厂家」

美亚的建档表里「生产厂家」最多 50 个字，而且它要的是**法定名**，不是单据上的原文。
单据上常写成「德国DMG化学医药集团公司DMG Chemisch-Pharmazeutische Fabrik GmbH」（53 字），
或者干脆只写个简称。

程序的做法是：

1. 注册证号命中 `config/manufacturer_aliases.json` 里的某一条 → 用那条的法定名（置信度 0.99）；
2. 原文与某条的别名精确相同 → 用法定名（0.96）；
3. 都命不中 → 原样保留（0.50），**并在报告里写「厂家未识别」**；
4. 写表时若仍超 50 字 → 在词边界截断并补「…」，本地库**保留完整原文**。

补别名表是长期活，报告里那些「厂家未识别」不是 bug，是待办。
格式见文件内的现有条目，关键字段：`canonical`（法定名，**必须 ≤ 50 字**）、
`license_nos`（注册证号，可以多个）、`matches`（单据上可能出现的写法）。

## 常见问题

**Q：为什么不直接对接美亚的接口，一键入库？**
A：不入库是**设计决定**，不是没做完。导入动作留在人手上：出表是批量、可复核的，
入库是不可逆的。而且美亚的导入接口没有源单据号字段，一旦导错，事后翻不出来是哪一单。
程序能做的都做了（表出对、号发对、账记对），最后那一下按下去的责任留给人。

**Q：产品库里同一个物品有两条档案怎么办？**
A：程序会把它挑出来，让你选一条（写进 `config/inbound_overrides.json`），
不会替你猜。根治办法是去美亚的产品库里删掉多余那条。

**Q：单据上某个物品本地库没有？**
A：进建档表。你把它导进美亚建档，再把美亚导出的产品库传回来（或直接从美亚复制
物品编号手工填），下一批就认得它了。

**Q：能不能只跑一部分？**
A：可以。`--in` 给单个文件就只处理那一个。

## 已知限制

- Windows 优先：.xls 转 xlsx 走 Excel COM；照片通道的批处理也是 Windows 路径最顺。
  其余平台需要先自己转成 .xlsx。
- 拉单依赖本机已登录的 Chrome/Edge（CDP 端口 9335），账号密码不由程序保管。
- 照片识别的准确率取决于拍摄质量，识别不出的行一定会阻断，不会静默丢行。
- 只针对「一张单据一批货」的常规版式；一单多页、跨页续表的版式需要新增 profile。
