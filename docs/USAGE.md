# 使用说明

这份文档讲「实际操作怎么走」：从装上到出表，遇到各个状态分别是什么意思、该做什么。
概念和设计原因见 [README](../README.md)。

---

## 一、装好之后先做两件事

### 1. 填自己的诊所名

打开 `config/platform_sources.json`，把 `YOUR_CLINIC_NAME` 换成你在平台上的收货单位全称：

```json
{
 "mmm": {
  "buyer": "某某口腔诊所",
  "supplier": "某某医药有限公司"
 },
 "yae": {
  "buyer": "某某口腔诊所"
 }
}
```

这个只用于核对「这张单是不是给我们店的」，填错不会崩，但判断供货商时可能认不出来。

### 2. 导入一次产品库

美亚 → 产品库 → 导出（得到 `产品库.xls`）→ 界面点「导入产品库」→ 选这个文件。

这一步很关键：程序**不联网读美亚**，它只知道你给它的这份库。库越新，误判越少。
建议每次在美亚新增了物品之后，重新导出导入一次。

导入结果会显示「新增 N / 更新 M / 跳过 K」。数字对不上时看界面上的说明，不要硬导。

## 二、跑一批：从单据到两张表

### 第 1 步：选目录

单据都放进同一个目录（可以是平台的导出文件、也可以是手机拍的照片）：

```
D:\单据\2026-11\
  ├─ 商品详情.xlsx          ← 牙e在线导出
  ├─ 销售清单.xlsx          ← 梅苗苗导出
  └─ IMG_20261120_1430.jpg  ← 供货商随货单照片
```

界面上「选目录」→ 选 `D:\单据\2026-11` → 「开始」。

程序会逐个认模板（按**表头签名**，不认文件名），认不出的直接报「阻断」，不会瞎猜。

### 第 2 步：看结果表

每一单一行，状态有这些：

| 状态 | 意思 | 你要做什么 |
| --- | --- | --- |
| **可入库** | 所有行都认出来了、也都建过档 | 直接导入库表 |
| **已出表** | 出过表了 | 导表，导完点「确认入库」 |
| **已出过表**（判重） | 台账里已有同号同明细 | 别重复导，否则库存翻倍 |
| **待建档** | 有物品本地库没有 | 先导建档表，再导入库表 |
| **待审批** | 有效期不足一年的行 | 确认货能用 → 点「同意入库」 |
| **多条档案** | 库里有 ≥2 条同身份档案 | 选一条（见下文） |
| **要补数据** | 一级分类推不出 / 数量为 0 | 在弹窗里补，补完重跑 |
| **禁止入库** | 有行被标成「不该进库存」 | 确认无误就重跑 |
| **阻断** | 模板认不出来 | 看提示，可能是新版式 |
| **全赠品** | 明细全是食品/饮料等 | 不用管 |

红灯状态点「处理待办」，弹窗里会把所有要你拍板的事列出来。

### 第 3 步：导表

产物都在批次目录里：

- `products.xlsx` —— 建档表。只有「待建档」的物品在这里，导进美亚「产品库」；
- `inbound_<供应商>.xlsx` —— 入库表，按供应商分组，一家一张。导进美亚「采购入库」。

**顺序很重要**：先建档，等美亚给回物品编号，再导入库表。
反过来的话，入库表里那些物品编号是程序临时发的，美亚里不存在，整行被拒。

### 第 4 步：点「确认入库」

表导进美亚之后，回到界面，在结果表下方找到「确认入库」那一块，
点对应单据的「确认入库」。

这一步之前，台账里只记了「已出表」；点了之后才记「已入库」。
两者分开是故意的：

> 程序只负责出表，它不知道你到底导没导。
> 如果出表就自动记「已入库」，某天你忘了导，台账上写着入库、库存里没有货，
> 月底对账会发现少了一批货却查不出是哪一单。

点错了可以「撤销」，撤销后回到未确认状态。

## 三、几种需要你拍板的场景

### 1. 效期不足一年 → 审批

美亚的规定是入库物品的有效期必须够长（默认要求 ≥ 1 年）。
单据上有些货只剩 8 个月，程序不会自己放行，会把它挑出来问你：

- **这批货能用** → 点「同意入库」。记录写进 `config/expiry_approvals.json`，
  这一行以后就认了，重跑不会再问；
- **这批货不能用 / 想让供货商换** → 点这一行的「这一行不入」（禁止入库）。

审批记录是按「单据号 + 物品名 + 有效期」三件套打键的。**换了效期就是换了货**，
旧审批自动失效，会重新问一遍 —— 这是故意的，不能让它拿旧批次的许可放行新货。

### 2. 某个物品不该进库存 → 禁止入库

赠品、样品、客户自备料这些不该入库存的，标「禁止入库」。

有两种标法，**很容易点错**：

- 展开单行，点那一行末尾的 **「这一行不入」** → 只标这一行；
- 单子底部那个大按钮 **「整单禁止入库」** → 整张单所有行一起标。

如果你只想挡掉其中一行（比如单据 5 行里只有一行是客户自备料），
一定要点行内的「这一行不入」，别点整单按钮。标错了可以在结果里撤销。

禁止入库是**永久判定**，与效期无关：标过之后重跑也不会再问。

### 3. 本地库同身份有多条档案 → 选一条

现象：你导了建档表，美亚回红字 **「该物品已存在」**。

原因不是程序判错了，而是**美亚的产品库里本来就有两条重复档案**
（同一个注册证+规格+品牌，两个不同的物品编号，通常是历史导入造成的）。
程序发现「这个身份能对上两条」，不敢替你选，于是把它挑出来。

弹窗里会出「多条档案待选」，每行列出候选：

```
甲硝唑棒 每100g含甲硝唑22g（2支/盒）· 库里 2 条同身份档案
  [ 10325 — 甲硝唑棒（内部 92013）  ▽ ]
  [ 10321 — 甲硝唑棒（内部 92008）  ▽ ]
```

选一个 → 保存 → 会自动记进 `config/inbound_overrides.json`，下次就认它。

> 根治办法：去美亚产品库把多余那条档案删掉。删不了就让它一直用 overrides 指定。

### 4. 一级分类推不出 / 拆包数量缺失 → 要补数据

这两项是美亚建档表的必填项，缺了整行会被拒。程序按关键词猜，猜不出就阻断。

弹窗里会给下拉框（一级分类只能选美亚分类树里的字面值）和输入框（拆包数量/单位）。
填完保存，重跑这一批就过了。填的值会记进 `config/manual_fixes.json`，
下一批同样的物品直接沿用。

## 四、核对台账

界面上「核对台账」会打开一个弹窗，把**程序记的台账**和**这次出的表**对起来。

| 列 | 含义 |
| --- | --- |
| 订单时间 | 下单/发货/开票的日期（**不是**我们出表的日期） |
| 单据 | 单号 |
| 来源 | 梅苗苗 / 牙e在线 / 其他 |
| 行数 / 金额 | 这一单的规模 |
| 本批 | 这张单在这批表里出现了没有 |
| 入库 | 有没有点过「确认入库」 |
| 记账时间 | 我们**什么时候出的表** |

默认按**记账时间**倒序排（台账首先是「我们哪天出的表」这本流水）。
要看订单本身的先后，点「订单时间」按钮切换。

来源可以过滤：全部 / 梅苗苗 / 牙e在线 / 其他。
「其他」不是垃圾箱 —— 平台认不出来时程序会退回供货商名，这些就归到「其他」，
免得按平台名过滤时整批漏掉。

弹窗顶上有五个数：这批单据 / 台账 / 已入库 / 未确认入库 / 对上。
「未确认入库」长期不为 0，说明有一批表出了但没导进美亚。

## 五、常见报错怎么办

| 美亚的回执 | 真正的原因 | 怎么办 |
| --- | --- | --- |
| 该物品已存在 | 产品库里同身份有两条档案 | 见「多条档案待选」；或去美亚删掉多余那条 |
| 生产厂家最多支持输入 50 个字 | 单据上的厂家原文太长 | 新版已自动截断；根治是把短法定名补进 `config/manufacturer_aliases.json` |
| 一级分类不能为空 | 关键词没命中分类树 | 弹窗里手选 |
| 内部编号已存在 | 上一批发过这个号但没导进美亚 | 程序会沿用 pending 里记的号；若仍冲突，查 `data/local.db` 的 products 表 |
| 采购数量必须大于 0 | 单据上数量是 0 / 读成 0 | 程序已阻断，先修单据 |
| 批号不能为空 | 单据没印批号 | 补齐后再导 |

## 六、它没做的事（别再问了）

- **不会替你导入美亚。** 导入是不可逆动作，且美亚的导入接口没有源单据号字段，
  导错了事后翻不出来。这一步留给人。
- **不会连美亚抓数据。** 代码里在 socket 层落了闸（`tools/no_meiya.py`）。
  产品库要你自己导出传进来。
- **不会替你决定「哪个物品是哪个」。** 身份对不上就打「待建档」，
  有多条档案就让你选，效期不足就问你 —— 全是明着问，不静默猜。
- **不会记住平台账号密码。** 拉单走本机已登录的浏览器（CDP），
  token 存 `config/*_token.json`，已被 `.gitignore` 排除。
